## Problem
`parsers/archive-list.js` scoped sub-category archives to `path: /en/<cat>/<sub>/`, but story URLs are flat, so the
7 sub-category archives could never show a story. The index carries only the top-level `category`, and WordPress
membership crosses parents (e.g. `/en/emobility/camouflage-to-get-you-hooked` is in Škoda World › Design), so a
parser-only fix was impossible.

## Change
1. `blocks/stories/stories.js`: new `categories` config key, any-of match against an index `categories` column
   (same semantics as `tags`). Configs without the key behave as before.
2. Story metadata (`transformers/skoda-metadata.js` + `skoda-metadata-extract.mjs`): new `categories` row, the
   `category-*` slugs of `article.post-<postid>` plus every ancestor. The ancestor tree is inlined (46 child→parent
   entries) and generated by the new `tools/importer/build-category-parents.mjs` from `/wp-json/wp/v2/categories`.
   `category` is unchanged.
3. `tools/importer/query-index-config.yaml`: new column:
   ```yaml
         categories:
           select: head > meta[name="categories"]
           value: attribute(el, "content")
   ```
4. `archive-list.js`: every `/en/category/...` archive (parents too) emits `template=story`, `categories=<slug>`
   with no `path`. Tag archives are unchanged.
5. All 19 import bundles rebuilt (byte-identical to a fresh rebuild; diff audited). `parsers/archive.test.mjs` has one
   expectation updated (the old `path` assertion); it merges cleanly with PR #253.
